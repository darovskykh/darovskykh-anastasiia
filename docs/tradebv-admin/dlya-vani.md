# Нова адмінка персони: що перенести в справжній фронт

Це клікабельний макет на фейкових даних. Вимоги: `vymohy.md` поруч.

## Як запустити

```bash
cd tradebv-front
npm install
npm run dev:mock
```

Відкрити http://localhost:8080/admin-dashboard/case-management/editor/mock-case-adrian (логін не потрібен, адмін підставляється автоматично).
Зміни зберігаються в localStorage браузера (`mock_api_db_v1`); щоб повернути початкові дані, видалити цей ключ.

## Що змінено

**Кейс → Основні**
- Прибрано «Брифінг» і «Фази (Progress widget)».
- Біля кожного поля бейдж, для кого текст: «Для AI» / «Для юзера» / «Для обох» (`src/components/AudienceBadge.tsx`). Розмітку треба підтвердити, див. нижче.
- Решта (поля, LLM, Дії користувача з діалогом) без змін.

**Кейс → Персона**
- Лишились: ім'я, роль, голос, Voice responses, прослуховування.
- Прибрано: Behavior engine, Опис персони, Стиль і мова, Обмеження поведінки, Внутрішнє міркування, Емоції, Реакції, Stateful controller V2.
- Додано «Стани персони» (`src/components/persona/PersonaStatesEditor.tsx`): стан → фази; у фази інструкція, дозволені переходи (зокрема в себе), принцип вибору переходу; стартова фаза; картинка емоції лише у фаз стану з позначкою «Відповідає за емоційну картинку» (такий стан один). Назви станів і фаз не захардкоджені. Під редактором карта переходів (`PhaseTransitionMap.tsx`).
- Додано «Факти (conditional facts)»: назва, умова, факт (`ConditionalFactsEditor.tsx`).

**Вкладку «Оцінка» прибрано.**

**Нова сторінка в сайдбарі «Базовий промпт»** (`src/pages/BasePrompt.tsx`, `/admin-dashboard/base-prompt`): промпт AI-співрозмовника, промпт AI, що веде діалог, універсальні факти, схема збирання інструкції (`src/components/prompt/PromptAssemblyScheme.tsx`, поки прикидка).

## Не переносити

Це лише для демо:
- `src/mock/*`, `.env.mock`, скрипт `dev:mock` у `package.json`;
- умова `VITE_MOCK_API` у `src/main.tsx`.

## Нові ендпоінти (назви полів попередні)

Типи в `src/types/personaStructure.ts`, виклики в `src/services/personaStructureService.ts`.

- `GET/PUT /personas/:id/structure` → `{ states: PersonaState[], facts: ConditionalFact[] }`
- `GET/PUT /base-prompt` → `{ talkerPrompt, controllerPrompt, universalFacts: ConditionalFact[] }`

Структура зберігається окремо від персони: у `handleSavePersona` і `handleSaveCase` після збереження персони йде `savePersonaStructure`. Картинка емоції зараз лише локальний object URL; потрібне справжнє завантаження файлу.

## Що варто знати

- **Копія відстає від проду.** Вона з `platform-source` (коміт `9d59c1e`), а на проді вже є «Reasoning effort» і модель GPT-6 Luna, яких тут немає. Переносити зміни треба в актуальний `Gart-tech/tradebv-front`, а не заміняти файли цілком.
- **Підписи полів не збігаються з назвами в коді** (`CaseEditor.tsx`): «Опис кейсу» це `roleInSimulation`, «Ваша роль» це `personaDescription` кейсу, «З ким ви спілкуєтесь» це `caseOverview`, «Флоу розмови» це `aiDescription` (`prompt`).
- **Стале пояснення.** У вимогах сказано, що стале пояснення для AI це «Опис кейсу / Ваша роль». А бекенд (`simulation_engine/prompts.py`) віддає AI «Флоу розмови» та «Правила поведінки сценарію»; «Опис кейсу», «Ваша роль», «З ким ви спілкуєтесь», «Навігація» бачить лише юзер. Бейджі й схема зроблені за бекендом. Треба узгодити.
- **Бейджі аудиторії, які треба підтвердити:** назва, інтро, опис кейсу, ваша роль, з ким спілкуєтесь, навігація: для юзера; флоу розмови, правила: для AI; у дій: назва для юзера, опис для AI, короткий опис для юзера, повідомлення в чаті для обох, текст попапу для юзера; ім'я й роль персони: для обох.
- **Нові тексти інтерфейсу написані українською прямо в компонентах**, не через `locales/*.json` (крім пункту сайдбару `admin.sidebar.basePrompt`).
- `handleSaveCase` досі вимагає `evaluationPromptId` / `finalEvaluationPromptId`, хоча вкладки «Оцінка» вже немає. Якщо оцінку прибирають назовсім, цю перевірку теж треба прибрати.
